# 4. User editing of the catalogue

**Priority:** P0 — the most underestimated part

- [ ] 4.1 Permission model: any registered user edits immediately (wiki style) / pre-moderation / reputation threshold / trusted editors only?
- [ ] 4.2 Edit versioning: do we keep the full change history of entities? Do we need diff viewing and rollback? (the change log is also a candidate feed for incremental delivery — see [10.4.7](10d-model-requirements.md), [10.1.10](10a-public-api.md))
- [ ] 4.3 Voting on edits (like MusicBrainz) or instant application (like Discogs)?
- [ ] 4.4 Duplicates: how do we find them and how do we **merge** entities while preserving references from users' collections.
- [ ] 4.5 Entity deletion: hard or soft? What if the release is in somebody's collection.
- [ ] 4.6 Reports/flags for incorrect data, a moderation queue.
- [ ] 4.7 Roles: user / trusted / moderator / admin. What rights does each have.
- [ ] 4.8 Reputation and contribution (how many edits were accepted) — do we need gamification?
- [ ] 4.9 Protection against vandalism and mass spam: rate limits, verified-email requirement, honeypot, reverting all of a user's edits.
- [ ] 4.10 Audit log: who, what, when, from where (IP) — what is the retention period.
- [ ] 4.11 Data entry guidelines (our own equivalent of the Discogs Database Guidelines) — are they needed and who writes them.
